# Meta-model for Kimi Linear: searching KDA memory recurrences on MQAR

This repository holds the code, candidate pool, per-run results and model weights
for a search over **per-head linear-attention memory recurrences** inside the Kimi
Linear (KDA) model. The task is multi-query associative recall (MQAR). Everything
except the state-update rule stays fixed: model wrapper, q/k/v/α/β feature
generation, readout, data and optimizer. Each candidate rule is a small typed DAG
generated by the DSL in `src/`.

It is shared so others can review the setup and check the numbers. Please open
an issue if anything looks wrong.

## Headline result (MQAR, length 2048, 256 key-value pairs, 10 seeds)

| Model | State update $S_t$ | Readout $y_t$ | Peak train acc. (%) | Final val. acc. (%) |
|---|---|---|---:|---:|
| Best Arch (C0274) | $S_{t-1} + [k_t \odot (\alpha_t + q_t - k_t)] q_t^\top$ | $\frac{S_t q_t}{\sqrt{d}}$ | 99.76 ± 0.11 | 99.53 ± 0.13 |
| C0041 | $S_{t-1} + (1+\beta_t) k_t q_t^\top$ | $\frac{S_t q_t}{\sqrt{d}}$ | 99.66 ± 0.12 | 99.41 |
| C0035 | $S_{t-1} + k_t q_t^\top + q_t (k_t \odot q_t)^\top + (q_t + v_t - \alpha_t) v_t^\top$ | $\frac{S_t q_t}{\sqrt{d}}$ | 99.39 ± 0.24 | 99.08 |
| KDA (official) | $S_{t-1} D_t + \beta_t (v_t - S_{t-1} D_t k_t) k_t^\top$ | $\frac{S_t q_t}{\sqrt{d}}$ | 19.33 ± 34.19 | 18.91 |

$D_t = \mathrm{Diag}(\alpha_t)$ with $\alpha_t = \exp(g_t)$ is KDA's channelwise
decay, and $\odot$ is channelwise multiplication. Values are means ± sample SD
over 10 seeds (model seeds 239–248 for the DSL candidates, 241–250 for KDA). The
DSL candidates use the same α/β/q/k/v ports as KDA, but some of them use α as a
write feature instead of as a decay.

**Caveats:**
- **Selection bias.** The three candidates were selected as the top of an
  adaptive 100-candidate screen (3 seeds each). The 7 extra seeds are fresh,
  but the selection itself is biased.
- **Optimistic primary metric.** The main metric is the raw peak training
  accuracy, i.e. the maximum over 20,000 single-batch accuracies. This follows
  the Kimi Linear paper's reported quantity, and it is optimistic. The fixed
  1024-example final validation accuracy is given next to it and is the more
  conservative number.
- **Seeds vary jointly.** Model and data seeds change together, so seed-level
  differences do not separate initialization effects from data effects.
- **Unstable KDA baseline.** KDA is highly seed-dependent here: 2/10 seeds pass
  50% and 7/10 stay near chance. See `results/kda_baseline/ten_seeds.csv`.

## What is in the repository

```

PROTOCOL.md              MQAR training protocol shared by KDA and every candidate
src/
  graph.py               DAG representation, validation, canonicalization, exact KDA member
  sample.py              random proposal distribution over legal DAGs
  influence.py           symbolic Sprev / x_t influence checks
  affinity.py            conditional-affine dependency filter
  structured.py          500-candidate population generator (dedup by exact tensor polynomial)
  lower.py               symbolic lowering to S Diag(d) + Σ(S a) bᵀ + Σ v kᵀ (DPLR form)
  pretty.py              readable equation for any candidate
  semantic.py            polynomial identity used to deduplicate mutations
  backend.py             generic Triton recurrent forward/backward kernel generator (reference)
  fast.py                maps DPLR candidates onto FLA's chunked generalized delta rule kernel
  fast_gate.py           BF16 numerical gate: fast kernel vs. reference (forward + gradients)
  prototype.py           step-by-step reference evaluation
  model.py               swaps the KDA recurrence inside FLA's KDA layer for a candidate
  train.py, mqar.py      trainer (full-state resumable checkpoints) and MQAR data adapter
  vendor/                unmodified Zoology `multiquery_ar` generator (pinned commit)
  run_candidate.py       train one candidate with the reported protocol
tests/                   CPU unit tests for the DSL (pytest)
data/pool500/            the 500 candidates, semantic equivalence classes, sampling report, KDA reference
results/
  formal100/             100 candidates × 3 seeds, then top 10 × 7 more seeds (370 runs)
  mutation_loop/         hand-proposed mutations of the top parents (g000 done; g001 running)
  kda_baseline/          official KDA, 10 seeds, same protocol
```

## Pipeline

1. **Generate (`structured.py`).** Draw 500,000 random proposals from the DSL. Keep
   graphs that are valid, write nonzero information from a zero state, and
   lower to a DPLR form. Deduplicate by exact tensor polynomial, then sample
   500 candidates across structural strata. Exact KDA is kept as a separate
   reference and is not in the 500. Run with
   `python src/structured.py --output <dir>`. The result is byte-identical to
   `data/pool500/candidates.jsonl` (SHA256 `b32d18bd…`).
2. **Numerical admission (`fast_gate.py`).** Compare each candidate's chunked
   FLA kernel against the step-by-step reference. Tolerances are a forward
   relative L2 error of 0.03 and a gradient relative L2 error of 0.10.
3. **Formal screen (`results/formal100/`).** Train 100 of the 500 candidates
   with 3 seeds each. 32 had already started under an earlier 500×3 plan; the
   other 68 were filled by stratified random selection that did not look at
   scores. Rank by the 3-seed mean peak train accuracy; validation is never
   used for selection. The top 10 then get 7 more seeds. Totals: 324 runs
   completed and 46 failed (6 numerical divergence, 40 execution failures).
   Failed runs are kept and make their candidate ineligible; nothing was
   silently retried.
4. **Mutation loop (`results/mutation_loop/`).**
   - g000: 8 algebraic edits of C0274, C0041 and C0035, 3 seeds each (24/24
     completed). Best: g000m003, $\beta_t [k_t \odot (\alpha_t + q_t - k_t)] q_t^\top$,
     at 99.72% vs. 99.71% for C0274 on the same 3 seeds. That gap is within
     screening noise.
   - g001: 8 edits of g000m003. Still training; only the candidate list and
     planned runs are included.

## Running

Requirements: Python ≥3.10, PyTorch 2.7 with CUDA, Triton 3.3, and
[flash-linear-attention](https://github.com/fla-org/flash-linear-attention) pinned
to commit `7ab283715a50ecceec3a4982f275a5a7039d01c6`. The reported runs used
single A100-40GB GPUs, PyTorch 2.7.1+cu126, Triton 3.3.1 and Python 3.12.8.
`requirements.txt` lists the packages; FLA must be installed from the pinned commit.

```bash
python -m pytest -q tests
```

```bash
python src/run_candidate.py --pool data/pool500/candidates.jsonl --index 274 --seed-index 0
```

```bash
python src/run_candidate.py --candidates results/mutation_loop/g000_candidates.jsonl --name g000m003 --seed-index 0
```

`--seed-index i` uses model seed `239+i` and data seed `20261020+i`. Outputs go to
`$KIMI_DSL_DURABLE` (default `./runs`) and generated kernels to `$KIMI_DSL_SCRATCH`
(default `./scratch`). Runs can be resumed from `last_checkpoint.pt` with `--resume`.
The official KDA baseline takes about 20 minutes per run on one A100; candidate runtimes vary.

## Model weights

The final (step 20,000) model weights are attached to the
[GitHub Release](../../releases) as safetensors. They contain model weights
only: no optimizer state and no RNG state.

- `weights_formal_top3_10seeds.tar`: C0274, C0041 and C0035, 10 seeds each.
- `weights_mutation_g000.tar`: all 8 g000 mutations, 3 seeds each.

Each `.safetensors` file comes with a `.json` file that records its config,
seeds, peak train accuracy, final validation and the SHA256 of the full-state
checkpoint it was extracted from. To load one, build the model with
`model.build_model(config)` using that config and the candidate's graph, then
call `load_state_dict` with the safetensors weights.

## Data and leakage checks

The MQAR batches come from the unmodified Zoology generator. Each batch is
generated deterministically from (seed, step), and each sequence draws its own
256 keys and values. Within a batch, sequences share no (key, value) pairs, and
the key-set overlap is about 6%, which is the chance level. The training and
validation generator seeds do not collide. Every label equals the value paired
with the queried key in the same sequence's context.

The q/k/v/α/β features come from the unchanged FLA KDA layer, per token and per
sequence (projection followed by a causal short convolution). Only the
recurrence is replaced, and the reference kernel is strictly causal.
